## Regra Escolhida

- **Tipo de identificador:** Constantes (`static final`).
- **Regra:** `ConstantName`.
- **Propriedade:** `format`.
- **Expressão regular:** `^[A-Z][A-Z0-9]*(_[A-Z0-9]+)*$` (`UPPER_SNAKE_CASE`).
- **Severidade:** `error`.
- **Action utilizada:** `dbelyaev/action-checkstyle@v3`.
- **Ficheiro de configuração:** `checkstyle-129822.xml`.
- **Workflow:** `.github/workflows/checkstyle-129822.yml`.

A convenção para constantes em Java (Google Java Style Guide e Oracle Java Code Conventions) estabelece que campos `static` e `final` devem ser escritos em maiúsculas, com as palavras separadas por sublinhados (`UPPER_SNAKE_CASE`), por exemplo `MAX_SHIPS`.

## Teste Realizado

No ramo `checkstyle-129822`, foi introduzida deliberadamente no ficheiro `src/main/java/battleship/Main.java` a constante:
```java
public static final int maxShips = 10;
```
O nome `maxShips` violou a regra `ConstantName`, uma vez que começa por letra minúscula e utiliza a convenção *camelCase*. O Checkstyle detetou a violação, indicou a linha e ficheiro correspondentes e fez o Quality Gate falhar a vermelho no GitHub Actions.

Posteriormente, a constante foi corrigida para:
```java
public static final int MAX_SHIPS = 10;
```
Após o commit e push da correção, o Checkstyle validou o novo nome face à expressão regular e o Quality Gate terminou com sucesso (verde).

## Limitações

A regra `ConstantName` do Checkstyle assegura que o identificador de uma constante obedece ao padrão sintático definido pela expressão regular (neste caso, `UPPER_SNAKE_CASE`). No entanto, o Checkstyle não consegue verificar a adequação semântica do nome, isto é, se o nome escolhido é significativo, claro e representativo do valor ou da finalidade que armazena (por exemplo, nomes como `X` ou `VAR_A` cumprem formalmente a expressão regular, mas continuam a ser maus nomes de constantes). Além disso, esta regra verifica exclusivamente constantes, ignorando nomes de classes, métodos ou outros atributos.
